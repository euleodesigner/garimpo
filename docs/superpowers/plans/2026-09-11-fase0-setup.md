# Fase 0 — Setup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Colocar o projeto Next.js no ar localmente, com Tailwind configurado com os tokens de cor da identidade visual, `.gitignore`/`.env.example` corretos, um projeto Supabase novo provisionado, e os clientes Supabase (browser + server) conectados e verificáveis — a base sobre a qual as Fases 1-6 do roadmap (§11 da spec) serão construídas.

**Architecture:** App Next.js único (App Router) na raiz do repositório, TypeScript estrito, Tailwind v4 (tokens de cor via `@theme` em CSS — adaptação do texto da spec, que fala em `tailwind.config`, para a ferramenta atual do `create-next-app`, que não gera mais esse arquivo; o objetivo da spec — cores centralizadas, sem hex-code solto pelos componentes — é preservado). Supabase como backend (Postgres/Auth/Storage), acessado via `@supabase/ssr` com um client de browser e um client de server separados, seguindo o padrão oficial do Next.js App Router.

**Tech Stack:** Next.js 16.3.4, React 19.2.8, TypeScript 5, Tailwind CSS 4, ESLint 9, `@supabase/ssr@0.12.7`, `@supabase/supabase-js@2.116.0`, npm.

**Spec:** `docs/superpowers/specs/2026-09-09-lista-garimpo-design.md` (aprovada pelo dono do projeto) — este plano cobre só a Fase 0 do roadmap em §11.

## Global Constraints

- Frontend + Backend: Next.js (App Router) + React + TypeScript (spec §3).
- Estilização: Tailwind CSS (spec §3).
- Banco + Auth + Storage: Supabase — Postgres, Supabase Auth, Supabase Storage (spec §3).
- Sem bibliotecas pesadas sem necessidade (spec §3).
- Sem `localStorage`/`sessionStorage` para dados sensíveis — sessão via Supabase Auth (spec §3).
- Todo acesso a segredo/afiliação roda em Server Action ou Route Handler, nunca em componente client (Regra Inviolável #5, spec §2).
- Credenciais e segredos nunca vão para o código-fonte nem para o Git — ficam em variável de ambiente ou em tabela protegida por RLS (Regra Inviolável #4, spec §2).
- Paleta de cores fixa (spec §4): `bg #F5F0E8`, `ink #241E17`, `sub #6B5D4F`, `card #FFFDF9`, `line #E2D8C8`, `clay #B4552D`, `jade #1F6F5C`, `gold #C08A2D`, `danger #A8352B`, `whatsapp #25D366` — viram tokens de tema, nunca hex-code solto em componente.
- Versionamento: GitHub, fluxo commit local → push → deploy automático no EasyPanel (spec §3). Este plano não faz `git push` — só commits locais; push fica a critério do usuário.
- Gerenciador de pacotes: npm (spec §10).
- Variáveis de ambiente do projeto (spec §7.4, §10): `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, `RESEND_API_KEY`, `NEXT_PUBLIC_APP_URL`, `NEXT_PUBLIC_ROOT_DOMAIN`.

- [ ] **Step 4: Criar o client de server**

`src/lib/supabase/server.ts`:

```typescript
import { createServerClient } from "@supabase/ssr";
import { cookies } from "next/headers";

export async function createClient() {
  const cookieStore = await cookies();

  return createServerClient(
    process.env.NEXT_PUBLIC_SUPABASE_URL!,
    process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!,
    {
      cookies: {
        getAll() {
          return cookieStore.getAll();
        },
        setAll(cookiesToSet) {
          try {
            cookiesToSet.forEach(({ name, value, options }) =>
              cookieStore.set(name, value, options),
            );
          } catch {
            // chamado de dentro de um Server Component (não pode escrever
            // cookie); inofensivo aqui porque o middleware de sessão
            // (Fase 3, spec §5) é quem garante a atualização do cookie
          }
        },
      },
    },
  );
}
```

- [ ] **Step 5: Criar uma rota de verificação**

`src/app/api/health/route.ts`:

```typescript
import { NextResponse } from "next/server";
import { createClient } from "@/lib/supabase/server";

export async function GET() {
  const supabase = await createClient();
  const { error } = await supabase.auth.getSession();

  if (error) {
    return NextResponse.json({ ok: false, error: error.message }, { status: 500 });
  }

  return NextResponse.json({ ok: true });
}
```
